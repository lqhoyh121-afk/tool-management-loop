# T01 待办完成与明确审批分离实测

> 历史阶段记录：当时状态已由 [最终交接报告](T01-HANDOFF.md) 更新；不作为当前验收或资源状态。

## 完成事件回读

真人确认已勾完成后，对同一 taskId 独立 get：isDone 从 false 变为 true，finishTime 从 0 变为实际时间。activities 比较前后新增 task.self.done 与 task.done，各有不同 activityId；两者 creatorId 一致且精确匹配 executorIds 内部人员ID，executorInfos/creatorInfo 显示本次指定管理人。活动ID、任务ID、原单ID及原始回执仅本机保存。

这是本次实际完成事件的操作者证据，不是只用指定执行人或 modifierId 推断。通讯录userId与待办内部ID仍属不同命名空间，本次创建参数和返回 executorInfo/事件构成实际映射观察，不将姓名当作普适身份转换接口。创建人和执行人为同一人，其他角色完成或代勾场景尚待反向实测。

勾完成后详情只有完成事件，没有明确同意/拒绝字段；此时评论列表为空且 hasMore=false。故本条回执不能当作审批同意。本结论是接口语义观察，不代表尚未开发的业务放行程序已通过闸门测试。

## 明确审批入口候选验证

在同一授权隔离 Base 内另建单笔审批收集表，使用真实单选字段“审批结果”，选项仅同意/拒绝，必填；附带可选意见及系统 creator/createdTime。仅指定审批人可填写，管理列表核对为本人；匿名及提交后修改关闭。未替人选择或提交，单页查询结果为空。

本页仅对应这笔原申请，说明正文包含准确原记录和关联待办引用，独立 view get 回读校验；已发布并从真实填写链接看到审批两项均未选中。待办附加一条明确标识为 Agent 添加且不是决定的入口说明，评论列表回读全文及评论ID核验通过。该评论发生在反向完成取证之后，不污染已保存的原回执。

此方法是单笔原生收集表承载明确决定的能力验证候选，不是 OA 审批流，亦不是冻结后的通用审批实现；原单引用为本轮受控配置及说明，不宣称平台提供不可篡改外键或自动防重复决策。规模化链接/并发/重复决定处理仍需主控在 T02 冻结。若主控要求 OA 专用审批，应另确认隔离模板授权，不冒充本轮已验 OA。

待真人在此入口作明确决定后，再回读选项、系统身份、时间和原单配置关联。尚未批准、预留、建立办理确认待办或改正式库存。错误身份尝试、管理人独立确认与测试清理仍未完成，L4 未通过，资源保留待测。
