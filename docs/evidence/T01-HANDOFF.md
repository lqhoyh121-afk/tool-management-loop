## 实际接口及字段形态

- `contact user search`：本次按指定姓名实时查找，唯一结果。`auth status` 与 `contact user get-self` 用于本人核验，不保存或公开令牌。
- `aitable field get`：身份字段类型 `creator`，时间字段 `createdTime`；业务数量 `number`，时间 `date`，审批结果 `singleSelect`。
- `record query`：`data.records[].recordId` 与 `cells[fieldId]`。creator 单元格是 `[{corpId,userId}]`；number 在本次回读为字符串，需显式数值解析；date 为带时区 ISO 字符串；singleSelect 为 `{id,name}`。不可用姓名输入代替系统 creator。
- `record query --all`：有数据时是顶层 `records`；空表曾返回 `records:null,hasMore:false,pages:1`，另用单页查询确认 `data.records:[]`。适配器须处理两种形态，不把 null 直接当异常或忽略业务错误。
- `view get`：`custom.formInfo` 含本次说明、分享标识、发布状态；`custom.requiredFields` 含必填字段映射。仅指定人范围由官方界面配置并检查。`view update --config` 曾受理但未改变必填，后用 UI 设置并回读，不能信受理成功。
- `todo task create --executors` 接受通讯录 userId；`todo task get` 返回 `result.todoDetailModel`，其中 executorIds、activities[].creatorId 是待办内部人员ID。通过创建参数、返回人员信息及事件形成此次映射观察，不把两个命名空间直接相等比较。
- 实际完成事件：`activities[].action` 为 `task.self.done`、`task.done`，带 `activityId`、`creatorId`；完成时间为 `finishTime`。没有明确审批结果字段。此次创建人、执行人为同一人，跨创建者映射及其他完成事件类型尚未验证。
- `chat message send` 用本人单聊、稳定 UUID；`message search` 独立回读完整正文和目标会话。初次搜索索引未出现时仅重查，没有重发。

## 清理与恢复

删除前再次精确读取每条任务及 Base，确认属于本轮隔离资源。删除三条待办后逐条 get 返回 `task not exist or operator not in task`，同时本人执行待办列表未包含目标ID；结合成功删除回执记录平台删除核验，不能把该混合错误单独解释为不存在。

Base 删除回执含删除时间；精确 get 返回 `BASE_NOT_FOUND`，同名搜索两页耗尽后结果为空；库存、申请、审批记录查询返回 `INVALID_BASE_ID`。两个共享表单链接重新打开均显示“表单已删除”。本轮 Base 下共有六张数据表（含默认及空的准备表），随整个 Base 删除。未清空其他业务表，也未执行回收站永久清除。

注意 Base 不存在时曾出现顶层 `success:true`，但 `status:error` 且 `error.code=BASE_NOT_FOUND`；必须检查业务状态和 error，不能将 success 布尔值当成功。

删除待办命令帮助中该子命令使用 `--yes`，首次用全局 `-y` 产生非 JSON 输出；先回查确认仍存在，再按帮助使用完整参数，未对结果未知的目标盲目重删。
