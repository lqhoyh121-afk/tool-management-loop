# T01 真人申请回读与待办反向测试准备

> 历史阶段记录：当时状态已由 [最终交接报告](T01-HANDOFF.md) 更新；不作为当前验收或资源状态。

## 已验证

指定申请人已由本人提交官方收集表。全量查询返回一条记录且 hasMore=false；按刷新后的字段映射核验工具名称、数量及含时区的归还时间，均与本轮授权相符。系统 creator 字段包含 corpId、userId，userId 与当次实时通讯录精确唯一申请人一致，corpId 与当前认证组织一致；createdTime 为系统提交时间。不是靠手填姓名认人。原始记录和身份标识仅在私有目录。

## 已建立的反向测试待办

创建前查询当前执行人待办列表，本轮原单未出现关联待办；先存意图，再给指定审批／管理人创建一条明确标识“仅勾选、不是同意”的测试待办。其标题包含真实原单引用，本机清单分别保存原单ID及待办ID；该关联是本轮人工设置的可回读引用，不是平台自动外键。

按 taskId 独立 get，核验标题、执行人展示信息、isDone=false、finishTime=0。当前仍等待真人只勾完成，Agent 未调用完成或审批接口。返回中人员标识是待办内部ID，与通讯录userId不是同一命名空间；executorInfos/creatorInfo 可读取姓名，但仅姓名不能证明真实完成者身份。activities 当前仅 task.create；需真人完成后继续取证，不预先将 modifierId 认定为完成者。

## 验收边界

可信申请身份阶段已有实际回读证据。明确同意／拒绝尚无证据；当前只在验证待办完成事件是否与审批决定有区别，没有开发业务自动放行程序，不能把“尚未写放行”当成已验证程序闸门。待办完成后的操作者证据、独立审批结果、指定管理人确认、申请人主账越权测试、错人完成和清理均待验证，L4 未通过。

恢复读取本机 resource-manifest.json 的 application 与 negativeApprovalTodo；先回读现有待办，禁止重复创建。所有测试资源仍保留待测，未清理。
