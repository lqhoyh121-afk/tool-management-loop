# T01 收集入口准备及首次权限观察

> 历史阶段记录：当时状态已由 [最终交接报告](T01-HANDOFF.md) 更新；不作为当前验收或资源状态。

## 本轮进度

本人完成浏览器授权后，已通过官方收集表 UI 在本轮隔离 Base 内建立独立收集表，命名为“工器具借用申请（隔离测试）”。此表不同于先前 API 新建的普通申请表，后者仍为空，不作为收集结果源。恢复使用私有资源清单中 collectionTableId 和 collectionViewId，禁止按近似表名猜目标。

字段为借用工具、借用数量、预计归还时间。三项必填；归还时间显示格式为 YYYY-MM-DD HH:mm。收集表自动生成“提交人”(creator)和“提交时间”(createdTime)系统字段，未把可自填姓名当身份凭证。字段类型存在仅证明可用的证据入口，真实提交人和时间尚待真人提交回读。

已配置并观察：

- 谁可填写：仅指定人；管理列表只有本次指定申请人。
- 匿名填写关闭；允许填写者查看并修改关闭。
- 表单发布后 UI 显示分享已开启及仅指定人可填写，CLI 回读 formInfo.status='1'、authTypeCode='2'。代码值仅记录本轮 UI 对照事实，不据此冻结通用枚举契约。
- 独立回读 requiredFields，三个业务字段均为 true。日期 formatter 独立回读包含分钟。
- 主 Base 的分享面板显示“仅文档协作者可访问”；未给申请人主账协作权限，未开启公开主账链接。

## 真实反向观察

当前审批／管理人本人会话访问已发布填写链接，页面显示“你无需填写此表单”，未显示填写入口。该人不是指定申请人；此观察证明本次页面入口限制生效，不替代服务端伪造提交测试，也不证明其他所有权限均正确。

真人提交前，record query --all 返回 records=null、hasMore=false；另用单页真实查询返回 success=true、data.records=[]，确认当前收集表无记录。Agent 未代提交任何申请。

## 发现的工具差异

通用 view update --config 传 custom.requiredFields 时返回成功，但独立回读并未改变必填配置；名称更新有效。改由官方 UI 逐项打开真实字段容器并设置必填，独立回读后才确认生效。不得用受理响应替代核验。date 字段支持的具体显示格式由 UI 选择后再回读取得，未猜写枚举。

Chrome MCP 将快照写往本轮私有目录时被其 workspace roots 拒绝，未改白名单或尝试绕过；改用工具返回的文本进行即时观察，不宣称保存了该快照文件。CLI 非凭据回执仍按已授权方式保存在原私有目录。

## 下一步与未验证项

等待指定申请人本人打开填写链接，提交本轮授权的申请内容和约定归还时间。提交后按精确收集表回读记录 ID、creator 和 createdTime，并与当次联系人身份关联。申请人能否打开主 Base 及改库存需其本人侧实测。

明确审批结果、仅勾待办不等于同意、管理人真实完成者、原单关联、错人办理和清理仍未验证。尚未创建审批或办理待办，未代做人工作业，L4 未通过。全部本轮测试资源尚保留待测，清理待完成后按精确 Base 及新增待办范围实施并回读。
