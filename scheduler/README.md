## 范围

只做扫描驱动提醒：扫描新记录触发流程所需提醒；不做库存增减、权限判断、审批确认状态推进（属 workflow），不实现调度引擎本体（阶段二等 T02 冻结后开始）。单机单实例；状态持久化，进程启停可见，不能因关闭聊天或进程退出丢失任务。

Loan 记录字段名【待 contracts 冻结】；去重键正式形态【待 contracts 冻结】，以下仅给语义组成。

| # | 用例 | 触发条件 | 所需 Loan 字段（待冻结） | 预期动作 | 去重键语义（待冻结） |
|---|---|---|---|---|---|
| C1 | 仅借用中提醒 | 记录处于借用中阶段 | 当前阶段、借用人、原单引用 | 只有借用中记录参与提醒计算；其他阶段一律不触发 | 记录身份+提醒种类+业务日期 |
| C2 | 提前一天一次 | 预计归还日前一业务日到达 | 预计归还日、借用人 | 给借用人发一次提醒 | 记录身份+"提前一天"+业务日期；同日重复扫描不补发 |

## 测试计划占位（阶段二）

注入时钟（不修改生产系统时间）、持久化防重键、重启后同日不重复、不同记录不串单、C4/C5 暂停与恢复、C8 回查不盲发、C9 晚启动边界。测试用显式标注的合成实现，不连真实钉钉、不发真实消息。

## 对 contracts 的消费需求清单（供 #2，不是定义）

1. Loan 当前阶段与"归还待确认""写入结果未知"的判别依据（状态字段或等价形态）。
2. 预计归还日字段：带时区，业务日期按 Asia/Shanghai 口径换算。
3. 借用人/管理员的身份引用与区分方式（含两身份命名空间映射证据要求）。
4. 提醒发送接口：输入、回执（成功/失败/未知）、可回查性；未知结果的回查接口。
5. 防重键的持久化载体约定（本地运行流水的一部分，非第二主账）。
6. 运行水位/已发标记的持久化与重启语义。

## 主控待决定项（准备段整理呈现，不替主控决定）

| # | 待决项 | 依据与建议 |
|---|---|---|

| D2 | 晚启动补发策略 | 建议只补当天一次（C9）：错过当日触发时刻的进程启动后补发一次，不回溯多日 |
| D3 | 到期日/逾期起算口径 | "提前一天"以预计归还日前一业务日为准；逾期自预计归还日后第一个业务日起算——需确认是否含当日边界 |
| D4 | 发送时段限制 | 是否限制在特定时段（如工作时间）发送提醒；逾期待决 |

## 实现（实现段，2026-09-15）

`scheduler/reminder.py` 纯求值 + `scheduler/runner.py` 编排，消费冻结契约（`Loan.state`/`due_at`、`business_date`）：

- 评估规则（`evaluate`）：仅 `borrowed` 参与提醒；归还待确认（含归还写入未定的可见形态，契约 §3"保持旧业务状态"）暂停；预计归还日前一业务日发一次 `before_due`（键含预计归还业务日）；到期日当天起每业务日一条 `overdue`（键含当天业务日，接线侧按发送日是否等于到期日区分「今天到期」/「已逾期」文案）——跨天停机自然合并为启动日一条。
- 窗口（`ReminderRunner.run`）：Asia/Shanghai 09:30 前/18:00 后不发送；注入时钟，不触碰系统时间。
- 防重与回查：发送结果 unknown 记入 pending，先按原键回查（确认送达→落 sent；确认未送达→允许一次重发；仍未知→该单当日阻断，不换日期键绕开）；`FileDedupStore` 以 JSON 文件持久化 sent/pending/启停状态，重启不重发——它是本地运行流水，不是第二套库存主账。
- 收件人恒为 `loan.borrower`，管理人不出现在任何提醒。
- 测试见 `tests/scheduler/test_reminders.py`（15 项，覆盖 C1-C9 与 D1-D4 边界；时钟/发送/查询全部合成注入）。
